# Phase 2 TPL runtime boundary

This phase activates an authoring-preview execution for all 180 structural coordinates: 20 ordered BASED Vibes × 3 Delivery Intensities for each of ASK, DEAL, and PRESSURE. Every coordinate is derived from its original candidate anchor, has a stable template variant, construction, protocol, gate disposition, provenance, readiness state, and deterministic rendered-fragment evidence. The records are `REVIEWED` and preview-eligible; they are not owner-approved production language.

## Runtime contract

Mechanics resolve the semantic action first. The adapter then supplies one typed semantic envelope to `resolveMatrixCell()`. The resolver validates the registered act construction, realizes safe human-readable slots, requires PRESSURE to carry a self-consistent actual/context-bound authored contract, applies the selected ordered Vibe and intensity, and returns written text plus a separate `faceRequest`. Demo scenarios are inspection fixtures only and are not a runtime authorization registry. The renderer never mutates the semantic payload or face fields.

Context claims are fail-closed. Candidate-anchor gates are calculated per intensity. A gate is exact only when the caller supplies an object with the matching `requiredFact` and `authorized: true`; otherwise the same coordinate uses a neutral rewrite and records `NEUTRAL_SAME_COORDINATE_REWRITE`. `requireExactContext` rejects instead of rendering the gated candidate claim.

The nine legacy forms remain only in `renderSafeFallback()` as an explicit `PRODUCTION_SAFETY_FALLBACK`. Mapped coordinates reject every non-`AUTHORING_PREVIEW` execution mode until owner approval exists. Runtime corpus records remain zero.

Readiness is canonicalized by the persisted `readiness.state` projection: `PREVIEW_READY`, `REVIEWED`, `APPROVED`, `PRODUCTION_ELIGIBLE`, or `BLOCKED`. The schema constrains its agreement with lifecycle/status and eligibility fields. Current canonical-neutral matrix/templates/protocols are `REVIEWED`, preview-eligible, and production-ineligible; canonical-neutral is a validation/preview profile, not final ZANT production language. The unsupplied `ZANT_HUMOR_V01` profile is `BLOCKED`.

Semantic evidence is not a clone comparison. `validateRenderedTextSemanticEvidence()` independently checks that every required semantic fragment is present in the rendered text, that no residual words remain outside semantic fragments and explicit semantic-free presentation atoms, and that those atoms declare `semanticEffect: NONE`. The same mandatory fragments are checked across all three intensities.

## Style-profile seam

`renderStyleProfile()` is the single language boundary. `CANONICAL_NEUTRAL_V01` is deterministic, reviewed, and preview-only. It receives the fixed action, ordered Vibe (`vibeId`, `name`, `primaryCue`, `secondaryCue`), intensity, safe realized slots, coordinate, and authorized available facts. Leverage enters only through the validated realized semantic slot; the renderer cannot read or mutate hidden mechanics, state, or face evidence.

`ZANT_HUMOR_V01` is declared as a blocked, unsupplied profile. A later owner-supplied profile can replace the language recipe behind this function without changing mechanics, BASED definitions, coordinate identity, semantic slots, or invariance rules. Before enabling it, the profile must provide reviewed provenance, deterministic templates, exact-fact gates, no invented relationship/audience/deadline/knowledge/threat/promise/leverage/consequence/outcome, separate face handling, and the full 180-coordinate plus adversarial invariance suite.

The author CLI exposes the complete report, `inspect --coverage`, and `inspect --coordinate KEY`. No raw TPL atoms or style controls are exposed to players.
