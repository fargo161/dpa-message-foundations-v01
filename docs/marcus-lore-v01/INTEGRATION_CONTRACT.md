# Lore integration contract v1

H1 solely owns state.mjs, engine.mjs, marcus-policy.mjs, server wiring, old tests, validation scripts and shared docs. H2 owns history-content.mjs, knowledge.mjs, information-policy.mjs, new focused knowledge unit tests and its two docs. H3 owns conversation.mjs, messages.mjs and public/encounter plus its doc. H4 owns three specified independent acceptance test files and two reports. No nested delegation. All work is in this isolated worktree, never the old checkout. No push/public tunnel.

## Frozen interface

State keeps seven metrics; patience becomes 20, range 0..20. Add `lore` from H2 `createLore(seed)`. Add `phase` CONTACT/BUSINESS/NEGOTIATION/RESOLUTION, derived `outcomeQuality` at resolution. No new numerical gameplay meters. Existing terms and actions retain shape. DEAL may include optional `information: "NONE" | "OFFER_INFORMATION"` (omission means NONE). ASK uses topic only. No arbitrary prose, fact claims or hidden values in input.

H2 exports from knowledge.mjs: `createLore(seed)`, `loreOptions(state)` => array of {id,label,available,reason} for new ASK topics; `informationEligibility(state,intent)` => {allowed,reason}; `projectLore(state)` => {briefing:string[], playerKnowledge:string[], disclosed:string[], evidence:string[], informationOptions:array<{id,label,available,reason}>}. All strings in this projection must be player-safe; no hidden priorities/variant diagnostics. State lore shape H2 owns and documents. H2 exports from information-policy.mjs `resolveInformation(state,intent)` => {lore,scoreBonus:number,social:{confidence:number,tension:number},progressKey:string|null,causes:array,feedback:string,exchange:null|{factId:string,summary:string}}. Pure: never mutate arguments. Validate server eligibility before calling this. ACCEPT uses state.counteroffer.informationExchange; commits disclosure only then. Positive bundled offer/counter has informationExchange stored by engine. Full disclosure cannot later be offered as private. A rejected deal can reveal the category but never automatically deliver the promised detail. Negative opportunity expires after three subsequent turn positions and is consumed on the first later DEAL; no persistent numeric meter. `hasLoreFact` exposes grounded catalog presence for H1 reaction-cause references.

H2 new ASK topics: SMALL_TALK, ACK_MISSED, VERIFY_SOURCE, PROBE_USEFULNESS, DISCLOSE_PARTIAL, DISCLOSE_FULL, QUESTION_RECORD. Common topics must gate on relevant authored fact presence. H2 may refine labels and fact IDs; notify H1/H3 before interface changes. Positive and negative variants independently salted from seed; all six variant/quirk combinations reproducible. H2 supplies pure unit tests and seed examples.

H1 adds ASK CLARIFY_OFFER, valid only with current offer, preserves exact offer identity/version without terms or condition changes. Every other ASK and DEAL invalidates prior offers. API request version remains current events.length even when an offer's version is older. Clarification consumes patience; on exhaustion ends and invalidates offer. No social benefit from clarification. Existing counteroffers carry optional informationExchange; acceptance revalidates exchange eligibility too.

H1 policy accepts third argument informationEffect (default neutral). Add effect scoreBonus only after hard credit checks remain in force; add social effects before clamping. Replace global goodwill cutoff with first specific topic/fact progress and strictly improved financial concession record. Repetition ignores tone. No positive rewards for exhausted topics, repeated facts, cosmetically changed terms, or oscillating terms. At least one meaningful six-exchange route must fit patience 20. Keep canonical BASED reaction table/intensity unchanged. Generic PRIORITIES gives only shared ambiguous evidence; welcome probes can provide partial observations, never complete hidden diagnostic names.

H3 conversation.mjs exports `conversationView(state)` => {phase:string, opening:string[], nextSteps:string[], outcomeQuality:object|null}; `reactionCause(state,intent,decision,informationEffect)` => versioned cause object with turn reference, semantic intent, involved fact IDs, observed evidence, consequences, continuity and remaining avenues. No face slots or final emotion mapping. Engine writes event.reactionCause, event.progressKey, event.feedback and event.informationCauses (all structured causes Debug only). Existing event fields remain. Engine passes `{price,offer,state,informationEffect}` to playerMessage; decision gains `feedback` for marcusMessage. H3 must avoid presenting secret exact content until received; dialogue should use actual effects/known state.

Projection: existing play fields plus `lore:projectLore(state)` and `conversation:conversationView(state)`. play.events adds feedback but NOT reactionCause/hidden causes. options.topics combines baseline topics + H2 loreOptions + CLARIFY_OFFER, all with availability/reason. options.informationOptions = play.lore.informationOptions.
