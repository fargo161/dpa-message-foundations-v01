# DPA Keyword + BASED Matrix + TPL Synthesis Brief v0.1

## Governing architecture

> Lore establishes the situation. Mechanics resolve the move. BASED establishes the performance. TPL writes the performance. The face supplies separate supporting evidence.

The three source specifications describe complementary layers:

1. **EMP Lorebook and Human Logic** owns world facts, scoped knowledge, relationship roles, context, stats, obligations, action availability, deterministic outcomes, and attributable commonsense priors.
2. **DPA Message Builder / 180 BASED Matrix** owns the player-facing coordinate `semantic action + ordered BASED Vibe + Delivery Intensity`.
3. **TPL Intake Library** owns evidence, pragmatic constructions, written TPL atoms, protocols, compatibility, provenance, deterministic rendering, and semantic-invariance validation.

These layers must connect through typed contracts. They must not be merged into one opaque generator.

## Current milestone

Build the smallest authoritative semantic foundation that can support the later dialogue library:

- research, select, define, and implement 10–20 high-value semantic keywords;
- make them directional, typed, interconnected, inspectable, and mechanically useful;
- model human logic, material relationships, obligations, permissions, dependencies, knowledge, secrets, and emotional leverage;
- use them to expose concrete semantic actions under `DEAL`, `PRESSURE`, and `ASK`;
- connect resolved actions to all 180 `Vibe x act x intensity` coordinates;
- establish TPL intake contracts without yet attempting a large dynamic-language population pass.

## Definition of a keyword

A keyword is a compact semantic predicate or event/state operator. It is not a dialogue word, tone label, emotion label, prompt fragment, or finished sentence.

Illustrative candidates such as `OWES`, `NEEDS`, `CONTROLS`, `PROMISED_TO`, `TRUSTS`, `FEARS`, `RESENTS`, `KNOWS_SECRET_ABOUT`, or `HAS_LEVERAGE_OVER` are examples for investigation—not a preapproved final ontology.

Every selected keyword must declare:

- meaning and explicit non-meaning;
- category and typed argument roles;
- directionality, reciprocity, symmetry, or inverse relationship;
- positive, negative, historical, conditional, and disputed forms where applicable;
- compatible entity/resource types;
- context gates and blockers;
- related stats without collapsing the keyword into a stat;
- action affordances for `DEAL`, `PRESSURE`, and `ASK`;
- compatible and conflicting keywords;
- history facts and possible state transitions;
- research and project provenance;
- positive examples, boundary cases, and counterexamples.

## The 180-cell decision

The 180 matrix records are canonical performance coordinates, not 180 isolated final sentences.

Each coordinate eventually owns:

- action invariant;
- ordered BASED Vibe;
- intensity contract;
- universal semantic-safe fallback;
- allowed, preferred, and excluded TPL protocols;
- context-gated variants;
- separate face-compatibility requests;
- review and approval state.

The supplied 180 sentences are valuable authored anchors and test candidates. They must be audited before becoming universal fallbacks because some mention facts such as friendship, an audience, a deadline, alternate offers, vulnerability, social norms, or knowledge that may not exist in the semantic payload.

## Non-negotiable boundaries

- The player selects only a semantic action, one ordered BASED Vibe, and one Delivery Intensity.
- The player never selects raw TPL families, atoms, protocols, punctuation, face slots, hidden stats, or numeric Cue mixtures.
- BASED contains exactly five Cues and 20 ordered two-Cue Vibes. Order matters.
- Delivery Intensity is exactly `SUBTLE`, `BALANCED`, or `OVERT` and controls signal salience only.
- The legacy 70/30 convention has no semantic authority.
- Human-logic corpora supply attributable, defeasible authoring priors. They do not mutate live state or define BASED.
- TPL cannot change the actor, target, action, asset, quantity, price, deadline, condition, leverage, consequence, permission, ownership, or resolved outcome.
- A face and a written signal provide evidence, not proof of internal truth.
- No runtime language model is required.

## Phased roadmap

### Phase 1 — this package

Research and build the 10–20-keyword semantic core, repository connections, deterministic compiler foundation, 180-cell matrix structure, small reviewed fixtures, and TPL intake scaffold.

### Phase 2 — next move

Fill the TPL library with reviewed, dynamic dialogue language: constructions, atoms, protocols, contextual variants, compatibility mappings, and semantic-safe fallbacks.

### Phase 3 — subsequent refinement

Stress-test and fine-tune the keyword system for expansion, additional roles, actions, resources, contexts, packs, and author-created rules without schema collapse.
